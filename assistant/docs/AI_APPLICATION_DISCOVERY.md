## Entities and business workflows
Company owns Client and configuration. Client supports PM/PP/CD, raison_sociale or nom/prenom, code_client. FactureClient links company and client, creator, payment mode, optional source_devis/source_proforma; fields include numero_facture, date_facture, date_echeance, statut, devise, calculated HT/TVA/TTC and discounts. FactureClientLine recalculates totals through core BaseDeviFactureDocument/Line and signals. Existing invoice numbers are e.g. 0001/25, not an invented FAC format. Reglement links facture_client; only statut=Valide counts as paid. FactureAvoir subtracts active credit notes using AVOIR_ACTIVE_STATUSES. Devis/proformas can convert to invoices; invoice creation/edit UI uses CompanyDocumentFormContent; payments are managed in InvoicePaymentsSection. Document statuses: Brouillon, Envoyé, Accepté, Refusé, Annulé, Expiré. Payment statuses computed by FactureClientPaymentFieldsMixin: Payée, Partiellement payée, Non payée.

## Financial services and constraints

Dashboard KPICardsWithTrendsView.calculate_kpi_for_currency supports dated invoiced TTC less active credit notes, and outstanding balances. PaymentTimelineView computes valid collections by payment date. Existing dashboard queries include invoices regardless of document status: do not describe these as accepted-only revenue, accounting net revenue or profit. Existing totals and financial concepts are inconsistent in naming; expose precise metric labels and calculation basis, never profit. Separate MAD/EUR/USD; no conversion. TIME_ZONE=Africa/Casablanca. Some dashboard views convert Decimal to float; preserve documented source semantics and render currency with two decimals. Query parameters are not authorization; always recheck membership and constrain both invoice.company and client.company where resolving records.

## Security risks and integration decisions
Central engine is packaged once in this repository, initially hosted in facturation Django with a facturation adapter; no second login or unrestricted SQL. Database access occurs only in trusted bounded adapter handlers. Raw inference is private and independent of existing translation/OpenCode services. Scope conversations to user+company; resolve permissions on every tool call and before replay. Do not persist sensitive tool output in history or feed it back as permanent authorization. Reject unknown tools/arguments, external URLs and oversized requests; bound inference concurrency, query time and tool count. Approved workflow knowledge only, not arbitrary repository ingestion or production records. Financial access follows existing permissions as explicitly directed by the user.
